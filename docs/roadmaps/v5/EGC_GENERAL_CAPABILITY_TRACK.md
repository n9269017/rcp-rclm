# Empirical General-Capability Track — EGC-0 through EGC-6

## Purpose

The EGC track is orthogonal to the formal/executable phase sequence. It measures breadth, retention, transfer, robustness, unfamiliar-rule learning, and compute-normalized successor improvement.

It is not an AGI declaration, and no EGC score independently authorizes promotion.

## Track map

| Core phase | EGC counterpart | Public empirical question |
|---|---|---|
| 16 | EGC-0 | What broad capability profile does the frozen Phase 15/16 substrate possess? |
| 17 | EGC-1 | Can a horizon-independent controller allocate objectives and resources across domains without a host-authored route? |
| 18 | EGC-2 | Can independent reconstruction reproduce claimed cross-domain gains and rule out leakage? |
| X | EGC-3 | Do capabilities transfer across classical and selected noncommuting semantic representations? |
| Y | EGC-4 | Can proof production and proof-search policy improve without weakening root-checked validity? |
| Ω | EGC-5 | Does a successor-generated new representation or update language create a genuinely new empirical capability family? |
| Z | EGC-6 | Does long-running asynchronous operation yield retained, compute-normalized broad gains across unseen domains? |

## EGC-0 — frozen Phase 16 baseline

EGC-0 is the immediate empirical counterpart to the completed Phase 16 boundary.

The public protocol evaluates a predeclared package set that includes:

- the exact accepted Phase 15 terminal package;
- the predeclared Phase 16 campaign terminal set;
- one canonical Phase 16 terminal selected by a rule frozen before broad scores are visible.

The broad public domain categories are:

- mathematical reasoning;
- bounded theorem construction;
- program synthesis;
- repository repair and debugging;
- algorithmic optimization;
- scientific inference;
- constrained planning;
- retrieval and tool use;
- unfamiliar-rule learning;
- cross-domain transfer;
- perturbation robustness.

Exact task corpora, hidden prompts and answers, benchmark subsets, seeds, scoring code, transfer pairings, thresholds, and answer stores remain private until package and evaluator freeze.

## Measurement principles

For domain $d$, let:

$$
C_d(M)
$$

be the independently measured capability score of package $M$.

For a successor comparison:

$$
\Delta_d=C_d(M_{t+1})-C_d(M_t).
$$

A retained domain should satisfy a predeclared non-regression criterion, and a strictly improved domain should satisfy a predeclared positive lower-confidence criterion. Exact thresholds remain frozen private protocol material until evaluation closure.

The public report should record at minimum:

- number of improved domains;
- number of retained domains;
- worst-domain regression;
- cross-domain transfer gain;
- unfamiliar-task gain;
- compute-normalized gain;
- perturbation robustness;
- confidence intervals or equivalent uncertainty records.

No single aggregate score may hide a severe regression in a protected domain.

## Trust boundary

Every EGC stage must retain:

- package identities frozen before private task generation or selection;
- no task ID, prompt, answer, or successful route exposed to proposal or training systems before freeze;
- independent evaluation;
- raw prompt-to-output provenance;
- no task-indexed prewritten answer corpus;
- contamination and memorization checks;
- declared compute and evaluator-call accounting;
- public benchmark scores as descriptive evidence only;
- no benchmark score as independent promotion authority.

## Independence from the core phase

EGC evidence does not alter the core verifier or promotion authority.

The core phase may close structurally even if broad capability remains modest. Conversely, a broad benchmark gain cannot close a core phase without its required proof-carrying and replay evidence.

## Planned EGC-0 closure meaning

EGC-0 closes when its baseline protocol and results are independently reproducible. A low score does not invalidate the baseline.

No EGC stage in this roadmap claims completion.
