## Fixed meanings and canonical task selection

The inherited AE catalog contains 282 fixed task meanings. The production
language contains 32 descriptors at a source. These are distinct finite sets:
coverage of the producer grammar is not coverage of all constructible programs
or a guarantee that an unsolved contract has a reachable successor.

For a descriptor, the adapter evaluates the unchanged source and its finite
program append. It selects the least catalog index whose meaning fails before
and holds after. It rejects a descriptor for which no such index exists. A
candidate has no authority to alter the catalog, rename a contract, supply its
own verdict, or substitute a descriptor from another row.

The Lean interface proves soundness, leastness, and existence/nonexistence
conditions for this canonical task selection. With catalog completeness, an
absent selected task means that this appended descriptor realizes no missing
meaning within the fixed catalog. This says nothing about programs outside the
declared grammar.

`DomainBound` establishes the source parent, context shape, complete row-key and
descriptor pairing, and all family/variant slots. The actual selector's
counterfactual all-rejection order covers those 32 rows without repetition.
This order is used for coverage and is not presented as actual evaluator history.

The constructive offer builder derives the update key, program, task, task name,
parent, context, finite append, and proposal prefix. It uses the cumulative
charges derived from the checked reference-work journal.
The evaluator enforces the domain/context binding and offer binding before
calling AG's checker. Successful evaluation therefore supplies the exact row
and task association together with the existing guarded accepted-step relation.

## Truthful controller evaluation

Every actual receipt is derived from the selected source, exact controller
prefix and decision, the fixed evaluator identity, semantic observations, AG
obligation result, and current reference-work journal head. Rejected receipts
remain separate from prospective final-true proposals. A prospective proposal
is accepted evidence only when its complete recomputed acceptance check passes.

The adapter calls the unchanged controller's `decide` and `record_evaluation`
functions. It checks the selector against the independently reconstructed table
and verifies each resulting checkpoint through the inherited restore function.
The Lean truthful replay checks every Boolean against the evaluator at that
same prefix, projects to the existing controller replay, retains its invariant,
and refuses forged verdicts or continuation past a terminal state.

A complete truthful exhaustion covers every producer row. A credit stop concerns
only the inspected prefix. Resource denial is a distinct adapter outcome: the
controller can still be waiting to evaluate its next candidate. It is not
relabeled as controller exhaustion or global successor nonexistence.

## Conditional reference-work authorization

Inspection fuel is not resource authority. Each session takes a separately
anchored grant tied to its source, package, history, context, request, catalog,
and evaluator. The grant declares a bounded reference-work policy. The issuer
field is explicitly a reference test authority with `issuer_authenticated=false`
and `campaign_authority=false`; a digest does not create issuance authority.

One attempted candidate reserves one descriptor admission and two bounded DSL
probe records. Each probe compares the matrix implementation with the independent
reference interpreter. The inherited tariff assigns the per-attempt counter
vector `(1, 2, 8, 8)` and cost 112. These are declared reference units, not host
CPU, memory, wall time, energy, or a complete accounting of all Python calls.

The original preparation writes and flushes each reservation before the associated
operation, then records its result. An interrupted operation leaves a reserved
charge without a result. No later receipt is fabricated and no charge is refunded.
A preflight refusal for an incomplete attempt calls neither descriptor admission
nor either DSL probe operation for that refused candidate. Earlier source and
catalog verification remains outside this narrow charge profile. The Lean
authorized transition similarly reserves the
declared work before a truthful receipt can advance the controller. Successful
authorized replay retains the expected grant, exact charge sequence, and policy
bounds. Source-stale or substituted grants cannot authorize that replay.

Saved-evidence verification recomputes deterministic journal bytes in memory.
Those verification objects are not represented as newly persisted reservations.
The five original journal files are copied into the gate evidence only after
their exact bytes match the preparation packet. The plan binds their individual
hashes, and reconstruction checks the retained inventory and bytes against those
anchors. Both the smaller committed evidence and the complete recovery archive
retain these original journals.
The tariff excludes inherited source/evidence reconstruction, grammar generation,
planner scoring, hashing, controller bookkeeping, catalog scans, AG checks,
verification calls, journals and filesystem work, proof compilation, testing,
historical work, and future campaigns. Full campaign authority and complete
resource accounting therefore remain open.

## Validation and recovery contract

The application declares 115 Python tests. Finalization reads the anchored
packet under its strict CJSON-V2 contract; checkpoint manifests retain their
distinct canonical serialization. Regression cases exercise finalization with
the actual packet and original journal bytes and reject substitutions or
noncanonical encodings. The gate retains the explicit
completed-stage parent protocol: 35 formal stages comprise nine fresh module
compilations, nine direct import-resolution checks, one positive certificate
with 65 ordered named theorem audits, and 16 designated negative controls.
The positive certificate audits its exact ordered theorem inventory. Negative
controls must fail only at their intended final false assertion; unrelated
errors, warnings, timeouts, or unobserved native outcomes cannot count as success.

The tested source/tree, packet and generated proof bytes, pinned environment,
native compiler outcomes, compiled objects, and complete parent chain remain
bound. Saved-evidence reconstruction reopens that retained material without
launching the compiler or historical campaigns. The same sealed helper and
additive payload are used for the complete Linux application and the later,
separately attributed Windows run.

An interrupted installation cannot be taken over from a missing process handle.
Checkpoint contents and old evidence retain their historical states. Recovery of
compiled evidence requires the source and exact pinned environment; automatic
relocation is not claimed.

`source_bound_controller_evaluation_checked`. Only the complete actual pinned
