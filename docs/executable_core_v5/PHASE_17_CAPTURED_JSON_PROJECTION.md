## The premise addressed

S's Lean interpreter computes the routes of the original protected prompts from
typed `Phase17Routing.Value` inputs. Python previously parsed the captured JSON
files and emitted those values. S checked routing over the values, but its
certificate did not check their interpretation from the complete JSON bytes.

T supplies a total bounded decoder for the declared canonical ASCII JSON
profile. The selected certificate decodes the complete captured images directly
to S's actual eight package fields. Its final theorem composes those byte-to-value
bindings with S's protected routing, R's tensor interpretation, and Q's selected
finite-model acceptance result. The proof targets the imported S values; an
unrelated newly supplied value cannot replace them.

## Declared JSON reference profile

The decoder supports null, Boolean values, signed integers, unescaped printable
ASCII strings, ordered arrays, and objects with strictly increasing unique keys.
It rejects whitespace outside strings, trailing input, duplicate or reordered
keys, leading-zero integers, negative zero, decimal/exponent notation, escape sequences, and
non-ASCII bytes. These restrictions describe the selected canonical file profile;
they do not assert support for every JSON document.

The declared bounds are 65,536 bytes per document, depth 20, 1,024 array elements,
256 object fields, 8,192 characters per string, and signed 64-bit integers.
Boolean values remain distinct from integers. A successful result consumes the
entire input. Failure or exhaustion returns no decoded value.

The Python preparation implements the same admitted reference profile and
compares the result with the repository's strict JSON reader. That comparison is
development evidence. The formal certificate evaluates the Lean reference
decoder on the captured bytes and proves equality with the S fields.

## Formal composition

The selected byte-to-value equalities cover all eight documents on each side of
the transition. Package reconstruction retains the S adapter image and replaces
the eight typed fields with their decoded values. Equality with the imported S
package transports the original protected prompt routing and its decoded goal
and information bindings. The final selected statement retains Q's finite-model
accepted step and R's captured tensor projection witnesses.

The two selected protected JSON collections are byte-identical. The certificate
still emits both complete collections separately: it evaluates the eight before
decodings, then transports those equalities only after Lean checks equality of
the full after/before images and the actual imported S packages. A matching
digest alone does not discharge those equalities.

The complete byte literals are grouped into chunks of at most 256 values. Their
data definitions are marked `noncomputable` to avoid generating executable code
for large literal declarations. The decoder remains total, and the selected
equalities are checked by Lean's kernel with `decide +kernel`.

The two new scoped flags are `canonical_json_projection_checked` and
`protected_execution_from_json_checked`. They become true only after the actual
pinned Lean gate accepts the positive certificate and the required negative
controls are rejected for their intended false propositions.

The latter flag refers to execution in the declared Lean reference semantics.
Physical capture, digest authenticity and Python execution remain external. T
does not establish general JSON parser equivalence, Unicode/escape handling,
arbitrary transformer behavior, or a full physical/root accepted transition.

## Fresh proof checking and retained evidence

Each T gate creates a fresh external import directory and compiles Q, R and S as
three source-bound dependencies in that order. R and S dependency sources retain
their proved statements while removing only their exact named audit print
commands. The checker verifies the Q import used by R, the R import used by S,
and the S import used by T against those exact artifacts from the same run.
Previous success reports or compiled dependency artifacts cannot replace these
compilations. The pinned foundation import-cache assumption remains explicit.

The positive certificate must emit the exact named audit sequence with only
`propext`, `Classical.choice`, and `Quot.sound` as permitted axiom dependencies.
The source guards reject placeholders, new axioms, unsafe or partial definitions,
and native-decision shortcuts. Negative controls receive credit only for an
explicit false-proposition rejection. Missing imports, unrelated compiler errors,
timeouts, and interruptions do not satisfy that requirement.

Each negative case first proves by definitional equality that the decision of
its exact whole-value acceptance proposition is false. It then uses that checked
Boolean witness to simplify the attempted acceptance proposition to `False`.
An incorrect witness fails with an `rfl` error, which the unchanged strict
checker rejects even if Lean recovery also emits a later false-proposition
diagnostic. A real unmutated-input countercheck and saved-record regressions
cover this distinction. A stuck decision reduction is never credited as a
semantic rejection.

The gate retains source hashes, tool hashes, command streams, dependency artifact
hashes, import-resolution records and incremental formal progress. The completed
formal result must equal the retained progress record. Runtime and installer
tests use controlled malformed inputs and command records for rejection paths;
those fixtures are separately attributed from actual Lean evidence.
