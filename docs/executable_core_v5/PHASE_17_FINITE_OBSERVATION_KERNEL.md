## State, update, recovery, and nonvacuity

The state contains twelve typed frozen component images, installed program
keys and contents, theorem-observation tuples, numeric and named task frontiers,
the protected conditional-probability/goal observation, physical package identity,
and a fixed verifier identity. Inputs are freshly extracted from both packages.
They are not a list of caller-supplied success flags.

The update appends one installed program/key, inserts its numeric and named task,
and changes the package identity. The frozen images, protected observations and
inherited theorem observations are preserved. Update validity checks freshness,
the predecessor identity, the task-name mapping, and the bounded program shape.

The inverse consumes the actual finite successor: it removes the appended key
and program, erases the fresh task/name, and restores the update-bound predecessor
package identity. `exact_recovery` proves equality of the entire finite state.
This is pure observation-snapshot recovery, not active filesystem rollback or
proof of power-loss atomicity.

The base kernel satisfies all three immutable-root nonvacuity requirements:

- Its protected-value family distinguishes full protected views. Preservation
  applies to the actual typed images, theorem observations and protected data.
- Its residuals depend on declared work charges and the fixed total/dimension
  limits. The residual evaluator is nonconstant in its charge input: adding one
  candidate charge raises the total residual by 64. Different traces can still
  have equal total cost.
- Its structural containment relation rejects malformed transitions. An explicit
  rejected packet witnesses that the predicate is not universal.

Zero loss/recovery/goal/information budgets express exact preservation in this
model. Resource use is computed from the candidate update's bound charge trace;
the selected trace costs 4,032 units. Progress is the checked frontier cardinality. All inherited
base obligations, including typed successor, protected non-loss, recovery,
invariance, progress, trust, resources, structural containment and admissibility,
are supplied by the concrete finite model.

## Remaining boundaries

A successful Q gate establishes a concrete kernel and an accepted step for the
declared finite observation model. It does not establish the universal physical
observation refinement, full transformer/goal/information semantics, complete
resources, arbitrary-input capability equivalence, recursive-productivity
recertification, authenticated successor context, autonomous continuation,
active atomic promotion/rollback, required multi-seed/platform campaigns, or
Phase 18 independent replay.

The fixed current producer context is intentionally insufficient for an accepted
successor's next turn. A fresh context and authoritative lineage transaction
remain obligations. The retained P journal remains blocked and is not rewritten
as an accepted physical transition by Q.

Accordingly `finite_observation_kernel_checked` and
`finite_observation_step_checked` may become true only after the new actual
compiler gate. `root_transition_verified`, `full_learned_step_instantiated`,
`complete_learned_kernel_constructed`, physical refinement, full goal/information
interpretation, complete accounting, promotion and Phase 17/Gate E/EGC-0 closure
remain false. Assistant Linux validation and a later operator Windows run must
retain their own source identities and must never be conflated.
